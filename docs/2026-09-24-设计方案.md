# quanqiudaili-mcp 设计方案

- 日期：2026-09-24
- 状态：设计已确认，实施计划见 `2026-09-24-实施计划.md`；尚未编码。2026-09-24 按计划审阅结果更新了技术选型、目录结构、响应映射与安装方式
- 范围：全球代理对外 API（`externalapi`）的 MCP 适配层
- 上游文档：<https://develop.quanqiudaili.com/llms.txt>（Apifox 导出，每页内嵌 OpenAPI 3.0.1 YAML）
- 后端仓库：`proxy-distribution-system`，模块 `application/externalapi`

## 1. 背景与目标

把已经对外开放的 `externalapi` 接口以 MCP 形式提供给 AI 客户端（Claude Code、Claude Desktop 等），让模型能够查询子账号、库存、价格，并在用户确认后执行下单、续费、改配置等操作。

MCP 服务器只是一个 HTTP 客户端：业务逻辑、参数校验、鉴权、扣费全部仍在 PHP 后端执行，本项目不改后端任何代码。

### 已确认的决策

| 项 | 决定 |
|---|---|
| 项目形态 | 独立仓库，TypeScript，官方 MCP TypeScript SDK v2（`@modelcontextprotocol/server` 2.1），Node ≥ 20。面向其他使用者，环境要求与安装示例不以开发者本机为准 |
| 传输 | stdio 本地运行；远程 Streamable HTTP 不在本期 |
| 拆分 | 两个 server：`query`（只读）与 `manage`（增删改与扣费），同一代码库、同一份工具定义 |
| 鉴权 | 仅 token 模式，环境变量传入；不支持账号密码登录 |
| 购买接口 | `createProductBuyOrder` 拆成动态流量、时长 IP 两个 tool |
| HTTP 动词 | 查询类 GET，操作类一律 POST（后端已确认不校验动词） |
| 参数类型 | `product_type_id` 统一为整数 |
| 分发 | git clone 后本地构建，不发布 npm |
| 工具定义来源 | 从文档站 OpenAPI 生成，不手写 |

### 非目标

- 不覆盖前台 `api` 模块的接口。
- 不做 OAuth、多用户远程服务、token 自动刷新。
- 不在 MCP 层重做参数校验与业务规则，后端返回什么错误就透传什么。

## 2. 总体架构

```
Apifox 文档站 ──(开发期: npm run sync-docs)──▶ spec/pages/*.md + spec/overrides.yaml ──▶ spec/tools.json
                                                                                              │
                                                                                    (运行期: 只读本地文件)
                                                                                              ▼
AI 客户端 ◀── stdio ──▶ quanqiudaili-mcp [query | manage] ── HTTPS ──▶ https://admin.quanqiudaili.com/externalapi/*
                                                                         header: token
```

- 生成是开发期动作，输出提交进仓库；运行期不联网拉文档，启动即用。
- `query` 与 `manage` 是同一个可执行文件的两个启动参数，按工具的只读标注过滤注册。

### 技术选型

| 用途 | 选择 | 说明 |
|---|---|---|
| MCP 协议 | `@modelcontextprotocol/server` 2.1（SDK v2） | 官方 SDK，stdio 入口 `serveStdio`，兼容 2025 与 2026-07-28 两代客户端；测试用 `@modelcontextprotocol/client` |
| 参数校验 | SDK 内置：`fromJsonSchema()` + Ajv | 生成好的 JSON Schema 原样注册，`tools/list` 与文档一致；不引入 zod，不做二次转换 |
| 表单编码 | 自写 `toForm()`，基于 `URLSearchParams` | 约 10 行产出 PHP 括号格式，不加 qs |
| YAML 解析 | `yaml` | 仅 sync 脚本使用 |
| 测试 | vitest | 单元测试、以真实文档页为输入的快照测试、起本地假后端的 stdio 端到端测试 |

## 3. 文档到工具的生成规则

`scripts/sync-docs.ts` 的处理步骤：

1. 抓取 `llms.txt`，下载全部 `*e0.md` 接口页，提取 ```yaml 块并解析。说明页（`*m0.md`）与示例数据模型（`*d0.md`）跳过，Session 说明单独处理见第 8 节。
2. **按 `path` 合并**，忽略文档中的动词。同一路径在不同产品目录下各有一页，参数集不同。
3. **参数取并集**：query 参数与表单 body 参数合成一张表。必填规则：在所有变体中都必填才标必填；否则可选，并在描述中注明"对某类产品必填"。
4. **`product_type_id` 归一**：类型整数，枚举取该路径所有变体页的固定值，描述附中文标签：1 动态住宅流量不限时长、6 动态住宅流量包月、2 静态住宅普通、3 静态住宅原生、4 静态住宅运营商原生、8 数据中心。
5. **括号参数转结构**：
   - `content[0][id]`、`content[0][customUsername]`、`content[0][customPassword]` → `content: object[]`
   - `appoint_ip[0][ip_str]`、`appoint_ip[0][count]` → `appoint_ip: object[]`
   - `ids[]`、`subAccounts[]`、`sub_accounts[]`、`subAccountIds[]` → 数组
   - `searchArr[0]`、`searchArr[1]` → `searchArr: string[]`
6. **动词**：工具标注为只读则 GET，否则 POST。
7. **overrides.yaml** 按路径覆盖：工具名、中文描述、只读与破坏性标注、归属 server、参数描述补充、拆分规则、忽略页。文档缺陷的兜底修正也放这里，文档修好后删除对应条目。
8. 输出 `spec/tools.json`（MCP 工具形态：名称、标题、描述、JSON Schema、标注、路径、动词、固定参数），原始页面保留在 `spec/pages/`。脚本结束时打印与上一版的差异，供人工审阅后提交。

### 参数要点

- 分页工具描述注明 `pagesize` 最大 100。
- 购买与续费的 `num` 范围 1 到 300，来自后端校验规则。
- `order_buy_dynamic` 参数：`product_type_id`（1 或 6）、`num`、`bill_timelen`（仅 6 有效）。
- `order_buy_time_ip` 参数：`product_type_id`（2、3、4、8）、`num`、`timelen`、`agree`、`country`、`city`、`appoint_ip`、`exclude_ip_str`、`bandwidth_num`、`remark`、`use_ip_port`、`random_account_password`。
- `country` 一律为 ISO 3166-1 二字码，如 `US`，在描述中说明。

## 5. 鉴权与配置

| 环境变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `QQDL_TOKEN` | 是 | 无 | 由 `externalapi/user/login` 返回的 `data.userinfo.token`，有效期 30 天 |
| `QQDL_BASE_URL` | 否 | `https://admin.quanqiudaili.com` | 便于指向测试环境 |
| `QQDL_TIMEOUT_MS` | 否 | `30000` | 单次请求超时 |

- token 放请求头 `token`。
- 收到 HTTP 401 或后端返回"请先登录"类错误时，工具返回明确提示：token 无效或已过期，请重新登录获取并更新配置。不做自动刷新，因为刷新会使旧 token 失效，配置文件里的值随之作废。
- token 不写日志、不落盘。stdio 模式下 stdout 是协议通道，所有日志只走 stderr。

## 6. 请求与响应映射

- GET：参数进 query string。
- POST：`Content-Type: application/x-www-form-urlencoded`，用自写的 `toForm()` 生成 `content[0][id]=...` 这类 PHP 括号格式。
- 参数类型由 SDK 按 JSON Schema 在调用前校验，不符合时直接返回 `isError` 的校验提示，不请求后端。
- 响应统一为 `{code, msg, time, data}`：
  - `code === 1`：返回 `{code, msg, data}` 的 JSON 文本，`code` 归一为数字。不附 `structuredContent`。
  - 其它 `code`：`isError: true`，文本为 `msg`。
  - 非 JSON 或 HTTP 5xx：`isError: true`，带状态码与前 200 字符正文。
  - 后端限流"访问频繁"原样透传，并注明限额为每 IP 每分钟 180 次。

## 7. 安全与副作用标注

- query 工具：`readOnlyHint: true`。
- 删除与扣费工具：`destructiveHint: true`，`idempotentHint: false`；描述首句写明"会从账户余额扣费"或"不可恢复"，让客户端在调用前弹出确认。
- `manage` 启动时在 stderr 打印一行提示，说明该 server 含扣费与删除操作。
- 未在文档中公开的接口一律不暴露，例如 `accountDeleteAll`、`accountSwitch`、`account_verify`、`account_info`。

## 8. 资源

文档站的三篇说明页处理如下，已确认。

| 页面 | 处理 | 理由 |
|---|---|---|
| 动态IP Session验证（不限时长、包月两页，内容完全相同） | 做成一个资源 `quanqiudaili://docs/dynamic-proxy-session`，两个 server 都提供，随 sync 更新 | 这是用法知识而非操作：账号后缀参数 `cty`、`st`、`ct`、`ss`、`tm`、`spec` 的规则、正确与错误示例、资源池性能表。模型回答"怎么拿一个美国 10 分钟不变的 IP"时需要它 |
| 查询国家编码 | 不做资源 | `dynamic_country_list` 与 `static_country_list` 返回的是各产品实际可购买的国家与编码，比静态表准确；模型本身熟悉 ISO 二字码。只在工具描述里注明格式 |

不做本地拼接连接串的工具：连接串写法只以上述资源形式提供，由模型阅读后自行拼接。

## 9. 测试

- 快照测试：以仓库内固定的一份文档样本为输入，运行合并逻辑，断言生成 33 个工具、每个工具的名称与必填参数集合与预期一致。文档站变化时只需更新样本与快照。
- 单元测试：括号参数序列化 3 例；响应映射 3 例，分别是成功、`code 0`、HTTP 401。
- 联调：用测试账号把 query 的 19 个工具各跑一次；manage 只跑无资金影响的 `sub_account_update` 改备注。扣费类工具不在自动化中执行。

## 10. 安装与使用

要求 Node.js 20 或更新，Windows、macOS、Linux 均可。

```
git clone <仓库地址> quanqiudaili-mcp
cd quanqiudaili-mcp
npm ci          # 结束时自动编译到 dist/
```

Claude Code（`<安装目录>` 换成实际路径，Windows 也用正斜杠）：

```
claude mcp add quanqiudaili-query  -e QQDL_TOKEN=你的token -- node <安装目录>/dist/src/index.js query
claude mcp add quanqiudaili-manage -e QQDL_TOKEN=你的token -- node <安装目录>/dist/src/index.js manage
```

Claude Desktop 在 `claude_desktop_config.json` 的 `mcpServers` 中按同样的 command、args、env 配置。

## 11. 文档缺陷跟踪

| 缺陷 | 状态 | 生成器兜底 |
|---|---|---|
| 静态住宅普通子账号列表页路径写成 `/api/device/accountList` | 已修，线上确认 | 无需 |
| 索引描述与标题不符 | 大部分已修，"刷新Token"一条仍是"检测Token是否过期" | 生成只用页内 summary，不用索引描述 |
| 动词混用 | 规则已定：查询 GET、操作 POST | 按只读标注决定动词 |
| `product_type_id` 类型 string 与 integer 混用 | 规则已定：整数 | 强制整数 |
| `accountLimitFlowEdit` 旧页缺 `type`、`timelen`，`limit_flow` 非必填 | 待修 | 合并时以新页为准 |
| `accountLimitFlowEdit` 新页 `timelen` 为 string，`type` 描述仍写"0=不限时长" | 待修 | overrides 覆盖类型与描述：0 = 永久，按累计用量 |
| `accountLimitFlow` 两页 `product_type_id`、`id` 为 string，`id` 无描述 | 待修 | 强制整数，overrides 补描述 |
| 动态住宅（包月）国家列表页把 `product_type_id` 的固定值也写成 1 | 待修 | overrides 指定 enum [1, 6] |
| `ipStrList` 有一页把 `page` 类型写成 array | 待修 | 合并时标量优先并丢弃 items，overrides 指定 integer |
| `getBuyProductSku` 只有产品 2 那页把 `country_code` 标为必填，后端全要求 | 待修 | overrides 置必填 |
| `accountUpdateList` 的 `remark` 描述写成 "test" | 待修 | overrides 补描述 |
| 参数描述里夹着 `<a href>` 链接标签 | 文档站特性 | 生成时去掉 HTML 标签 |
| `common/stateList` 只有不限时长一页，后端对产品 1、6 都放行 | 文档缺页 | overrides 指定 enum [1, 6] |

## 13. 开放问题与后续
